# 스토어 등록 문구 초안

> 초안입니다. Play Console에 붙여넣기 전에 읽고 고치세요.
> 특히 **거짓이 되면 정책 위반**인 문장(네트워크·수집 관련)은 코드가 바뀌면 같이 고쳐야 합니다.

## 앱 이름

```
지인 기록
```

30자 제한. 검색을 노린다면 `지인 기록 - 사람 메모` 같은 형태도 가능하지만,
개인용 앱이면 짧은 쪽이 낫습니다.

## 짧은 설명 (80자)

```
만나기 전에 30초. 지인에 대해 아는 것을 기억해두는 개인 기록장.
```

대안:
```
사람마다 기억할 것을 적어두고, 만나기 전에 한 번에 훑어봅니다.
```

## 전체 설명 (4000자)

```
지인 기록은 사람에 대해 알게 된 것을 적어두고, 다시 만나기 전에 한 번에 훑어보는 앱입니다.

■ 만나기 전 30초
브리핑 화면 하나로 그 사람에 대해 필요한 것이 순서대로 나옵니다.
주의할 것, 아직 안 지킨 약속, 꺼낼 만한 화제, 최근에 만난 기록.
스크롤 없이 첫 화면에서 끝나도록 만들었습니다.

■ 잊어버리는 게 정상이라는 전제
사람에 대한 정보는 시간이 지나면 틀려집니다. 직장, 사는 곳, 요즘 하는 것 —
전부 언젠가 바뀝니다. 그래서 적을 때 "얼마나 잘 변하는지"를 같이 정하고,
오래된 것은 "확인 필요"로 따로 모아 보여줍니다. 틀린 것을 사실인 척 보여주지 않습니다.

■ 생일처럼 안 변하는 것은 따로
생일, 몇년생, 학번, 혈액형 같은 고정된 정보는 만료되지 않는 항목으로 따로 둡니다.
항목 이름은 직접 정할 수 있고, 한 줄로 넣습니다.

■ 관계를 그림으로
사람과 사람의 연결을 그래프로 봅니다. 나를 가운데 두고, 직접 아는 사람이 안쪽에,
건너 아는 사람이 그 밖에 놓입니다. 그룹은 벤 다이어그램으로 겹침을 봅니다.

■ 기기 밖으로 나가지 않습니다
계정도, 서버도, 광고도, 분석 도구도 없습니다.
인터넷 권한 자체를 요청하지 않으므로 앱이 통신할 방법이 없습니다.
백업은 직접 파일로 내보내고, 그 파일을 어디에 둘지는 사용자가 정합니다.
```

> **위 마지막 문단은 지금 코드 기준으로 참입니다.** 네트워크 코드가 들어가는 순간
> 이 문단과 데이터 보안 양식을 함께 고쳐야 합니다 — 안 고치면 허위 기재입니다.

## 스크린샷

Play는 휴대전화 스크린샷 **최소 2장**을 요구하고, 8장까지 받습니다.
순서는 앱을 처음 보는 사람이 이해하는 순서로:

1. **브리핑** — 이 앱의 존재 이유. 섹션이 두세 개 차 있는 상태로
2. **인물 목록** — 사람이 6~8명 있고 마지막 만남이 보이는 상태
3. **인물 상세** — 사실이 몇 개 있고 고정 정보가 채워진 상태
4. **관계도** — 나를 중심으로 선이 몇 개 그어진 상태
5. **그룹 맵 + 벤 다이어그램** — 원 세 개가 겹친 상태
6. **만남 기록** — 입력 화면

**가짜 데이터로 찍으세요.** 실제 지인의 이름·생일·건강 정보가 스토어 페이지에 영구히
남습니다. 앱의 설계 원칙 2("데이터는 기기를 벗어나지 않는다")와 정면으로 어긋나고,
당사자 동의도 없습니다. 빠른 추가 화면에 가짜 인물을 한 번에 넣을 수 있습니다.
